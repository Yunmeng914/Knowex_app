# Knowex 全面 UI/UX 优化基线

## 优化目标

本轮优化以“更少干扰、更少步骤、更清楚的状态”为目标，不改变工作区格式、设置数据、安全边界和外部集成协议。体验上可以组合阅读、批注、检索与问答，代码仍保持 Reader、Annotation、AI、Exa、Zotero 和 Settings 的独立模块边界。

## 当前用户任务与痛点

| 用户任务 | 当前主要路径 | 主要痛点 | 本轮目标 |
| --- | --- | --- | --- |
| 首次启动 | 引导页 → 工作区 → Zotero → 阅读说明 → 快捷键 | 可选配置进入主路径，说明偏长 | 先完成工作区和首篇 PDF，其他配置延后 |
| 打开文献 | 顶栏本地文件 / Zotero / 左侧最近文档 | 顶栏主次不清，未选工作区时仍能进入失败路径 | 根据状态给出单一主要行动 |
| 阅读与批注 | 阅读器工具栏 → 选择工具 → 页面操作 → 右侧编辑 | 工具栏图标过密，批注与后续动作分散 | 保留高频工具，低频显示在外观/更多菜单 |
| 管理批注 | 右侧列表 → 打开 → 编辑 → 删除 | 列表信息小、操作入口分散 | 提升字号，增加对象右键菜单与就地操作 |
| AI 问答 | 选择批注 → 右侧聊天 | 上下文明确，但设置说明和状态信息密集 | 保持批注上下文，精简说明并突出可执行状态 |
| Exa 检索 | 顶栏入口 → 原文上下文 → 筛选 → 指令 → 结果 | 筛选和提示密度高，大量 8–10px 文案 | 默认只显示问题与来源，高级筛选按需展开 |
| Zotero 导入/写回 | Zotero 入口 → 选择附件 → 同步确认 | 首次说明较多，条目操作依赖提示小字 | 将同步操作集中到条目上下文菜单和一次性说明 |
| 设置 | 设置 → 分类 → 卡片/表单 | 状态、帮助、安全说明重复，字号偏小 | 状态优先、帮助集中、保存反馈一致 |

## 视觉基线

- 当前样式中存在大量 `9px`、`10px` 和 `11px` 文本，重要状态、帮助与元数据难以区分。
- 顶部工具栏同时展示本地文件、Zotero、Exa、截图、工作区、双侧栏和设置，第一层操作过多。
- `dialogs.css` 同时承担设置、Zotero、引导、删除、路径和 Exa 等多类界面，后续应按功能逐步拆分，避免继续耦合。
- 颜色、圆角、阴影和控件高度仍有较多局部常量，需要统一到设计 Token。
- 右键菜单目前主要集中在阅读器和 Zotero 集合条目，最近文档、批注和 Exa 来源的快捷操作仍不完整。

## 本轮验收指标

1. 重要正文不低于 14px，按钮和输入内容不低于 13px，辅助信息不低于 12px；11px 只保留给非关键短元数据。
2. 顶栏可见文字按钮不超过三个，低频入口进入清晰的菜单。
3. 未设置工作区时，主界面首先引导选择工作区，不再让用户先进入文档打开失败路径。
4. 最近文档、Zotero 条目、批注和 Exa 来源具备一致的对象级快捷操作，其中高风险操作不只存在于右键菜单。
5. 设置、AI、Exa 和 Zotero 的长说明默认收敛到一个集中说明区域或按需展开区域。
6. 所有原有设置、凭据状态、同步入口和安全确认保持可用。
7. 通过类型检查、单元测试、生产构建、键盘检查和主要窗口尺寸视觉检查。
